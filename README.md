# CS-101126-APPS: Cardsite for Apple platforms

This repository holds the native Cardsite® apps for iPhone, iPad, Mac, Apple
Vision Pro and Apple Watch, with widgets, Siri and Shortcuts, and a share
extension. The apps are built to parity with the Cardsite web dashboard, on
the real API contract and the Studio design system.

## Build

You need a Mac with Apple silicon, Xcode 27 (Xcode 26 is the minimum App
Store Connect accepts) and XcodeGen 2.42 or later.

```sh
brew install xcodegen
cd platform/apps/apple
./scripts/doctor.sh                 # checks the paths the project needs
xcodegen generate                   # Cardsite.xcodeproj is generated, not committed
open Cardsite.xcodeproj
```

- **Schemes:** `Cardsite` builds the app for iPhone, iPad, Mac and Vision Pro, and embeds the widgets, the share extension and the watch app. `CardsiteWatch` builds the watch app on its own.
- **Run without a server:** add the launch argument `-CardsiteFixtures` (Debug builds only) to use the in-app fixture server.
- **Signing:** copy `Config/Signing.example.xcconfig` to `Config/Signing.xcconfig` and set `DEVELOPMENT_TEAM`. The extensions and the watch also need the App Group and the keychain group provisioned (A25).
- **Tests:** `swift test --package-path Packages/CardsiteKit` and `swift test --package-path ../../studio/packages/swift`, or ⌘U in Xcode for everything, UI tests included.
- **Design lint:** `scripts/lint-design.sh` (runs on Linux too).

## CI

[`.github/workflows/apple.yml`](.github/workflows/apple.yml) runs on pushes to
`main`, `claude/**` and `ws/**`, and on pull requests that touch the app,
StudioKit or the workflow. The macOS runners are the compiler, the test runner
and the camera, because the agent workspace has no Swift toolchain.

| Job | Runner | What it proves |
|---|---|---|
| `fixtures` | Ubuntu | The contract fixtures and the test copies match |
| `lint` | Ubuntu | No design literals in `Cardsite/` |
| `kit` | macOS 26 | `swift test` for CardsiteKit and StudioKit; CardsiteKit builds for watchOS |
| `app` | macOS 26 | The app builds for the iOS Simulator (with the watch app), macOS and the visionOS Simulator, and the watch app builds on its own, unsigned |
| `screens` | macOS 26 | The UI tests on iPhone 17 Pro Max, iPad Pro 13" and Mac. They run the journeys and capture every screen in light, dark and AX XXXL |
| `screens-publish` | Ubuntu | Commits the PNGs to the orphan **`screens` branch** under `runs/<sha>/`, with an `index.md`, keeping the last 10 runs |

Compiler and test errors become check-run annotations, so a failure is
readable without the raw log. The agents read screenshots from the `screens`
branch with git, because they can't download artifacts through their proxy.

A green run doesn't prove the app works against the real API on a device.
That is the device checklist in `native-apple.md`.
